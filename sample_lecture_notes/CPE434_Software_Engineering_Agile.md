# CPE 434: Computer Software Engineering I
## Lecture 3: Agile Development & Scrum Methodology

In modern software engineering, requirements change as users interact with increments.
Scrum provides an empirical framework based on transparency, inspection, and adaptation.

### Core Scrum Ceremonies:
1. Sprint Planning: The team establishes the sprint goal and pulls user stories into the sprint backlog.
2. Daily Scrum: A timeboxed 10-minute synchronization meeting to identify blockers.
3. Sprint Review: Live demonstration of the working software increment to stakeholders and lecturers.
4. Sprint Retrospective: Continuous improvement analysis of processes, tools, and team dynamics.

### Definition of Done:
A user story cannot be marked done unless:
- It compiles cleanly and runs on a teammate's machine.
- It was built on a branch and merged via an approved pull request.
- Automated tests pass and acceptance criteria are satisfied.
- Documentation and README are updated.
